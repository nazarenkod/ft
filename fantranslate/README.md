# FanTranslate v1.0 — UA Edition

Локальний CLI-інструмент для автоматизованого перекладу фанфіків по всесвіту
Гаррі Поттера **на українську мову** — з англійського або російського джерела.

```
EPUB / PDF  →  очищення тексту  →  переклад через Claude API
            →  готовий .docx з оглавленням і колонтитулами
```

## Можливості

- **EN→UK та RU→UK** — напрям задається флагами `--from {en,ru} --to uk`.
  Для російського джерела глосарій матчиться по російських формах
  (`Хогвартс → Гоґвортс`).
- **EPUB і PDF на вході** — глави витягуються по структурі книги (EPUB)
  або евристикою (`Chapter N`, ALL CAPS) після пайплайну очищення PDF
  (колонтитули, номери сторінок, розірвані рядки).
- **Переклад через Claude API** — три рівні якості (Haiku / Sonnet / Opus),
  глосарій кешується (prompt caching, ~90% економії на цій частині input-токенів).
- **Консистентність термінів — два рівні:**
  1. *Канонічний глосарій* у кешованому system-prompt (однаковий для всіх
     глав/чанків).
  2. *Авто-збір імен* — перед перекладом з усього тексту витягуються
     повторювані власні імена (ОС-персонажі, вигадані заклинання/місця),
     їм фіксується єдиний переклад на всю книгу. Вимикається
     `--no-collect-names`.
- **Пост-перевірка** — після експорту готовий текст сканується на різнобій
  написань (Гоґвортс / Ґоґвортс / без апострофа) і виводить попередження.
- **Паралельність** — до 5 глав одночасно (asyncio).
- **Resume-on-failure** — кожна глава одразу фіксується в SQLite;
  повторний запуск пропускає вже перекладені глави.
- **Оцінка вартості до запуску** — точна через `count_tokens` API
  або евристикою без мережі.
- **Експорт у .docx** — Georgia 12pt, інтервал 1.5, поля 2.5 см,
  зміст, колонтитул з назвою та номером сторінки.

```bash
cd fantranslate
pip install -r requirements.txt
echo 'ANTHROPIC_API_KEY=sk-ant-...' > .env
```

Вимоги: Python 3.11+, ключ Claude API (https://console.anthropic.com).

## Швидкий старт

```bash
# EN → UK (за замовчуванням)
python translate.py input.epub

# RU → UK
python translate.py input.epub --from ru

# Якість max (Opus) з виведенням у конкретний файл
python translate.py input.epub --quality max --output my_fanfic_uk.docx

# Перекласти тільки глави 1–5
python translate.py input.epub --chapters 1-5

# Перекласти без авто-збору імен
python translate.py input.epub --no-collect-names
```

Готові переклади зберігаються в `output/` (`<ім'я>_uk.docx`), прогрес — в
`translations.db`.

## Усі команди та флаги

### `translate` — основна команда

```
python translate.py translate [OPTIONS] FILE
python translate.py FILE          # скорочений синтаксис
```

| Флаг | За замовч. | Опис |
|------|-----------|------|
| `FILE` | — | EPUB або PDF файл для перекладу |
| `--output`, `-o PATH` | `output/<назва>_uk.docx` | Шлях до вихідного `.docx` |
| `--chapters SPEC` | всі | Вибір глав: `1-5`, `1,3,7`, `2-4,8` |
| `--from {en,ru}` | `en` | Мова джерела |
| `--to {uk}` | `uk` | Мова перекладу |
| `--quality {fast,balanced,max}`, `-q` | `balanced` | Рівень якості (див. нижче) |
| `--collect-names` / `--no-collect-names` | увімк. | Авто-збір повторюваних власних імен |

**Приклади:**

```bash
# Мінімум: перекласти весь файл
python translate.py book.epub

# Тільки перші 3 глави, дешева модель
python translate.py book.epub --chapters 1-3 --quality fast

# З російського, максимальна якість
python translate.py book.epub --from ru --quality max

# Зберегти в конкретну папку
python translate.py book.pdf --output /tmp/translations/book_uk.docx

# Без авто-збору імен (швидше, якщо імена тільки канонічні)
python translate.py book.epub --no-collect-names
```

### `resume` — продовжити перерваний

```
python translate.py resume [OPTIONS] FILE
```

Синонім `translate`: вже перекладені глави (з SQLite) пропускаються автоматично.

| Флаг | За замовч. | Опис |
|------|-----------|------|
| `FILE` | — | Той самий файл, що й при початковому запуску |
| `--output`, `-o PATH` | `output/<назва>_uk.docx` | Шлях до вихідного `.docx` |
| `--from {en,ru}` | `en` | Мова джерела |
| `--to {uk}` | `uk` | Мова перекладу |
| `--quality {fast,balanced,max}`, `-q` | `balanced` | Рівень якості |
| `--collect-names` / `--no-collect-names` | увімк. | Авто-збір імен |

```bash
# Продовжити перерваний переклад
python translate.py resume book.epub

# Можна змінити якість при відновленні
python translate.py resume book.epub --quality max
```

```
python translate.py clean [OPTIONS] FILE
```

Запускає пайплайн очищення PDF і показує результат без перекладу.

| Флаг | Опис |
|------|------|
| `--preview` | Показати перші 500 символів кожної знайденої глави |


### `glossary add`

```
python translate.py glossary add ENGLISH TRANSLATION [--lang {uk,ru}]
```

Додати або оновити термін у глосарії.

| Аргумент/флаг | Опис |
|---------------|------|
| `ENGLISH` | Англійський ключ (канонічна форма) |
| `TRANSLATION` | Переклад на вибрану мову |
| `--lang {uk,ru}` | Мова перекладу (за замовч. `uk`) |

```bash
# Додати/виправити українську форму
python translate.py glossary add "Snape" "Снейп"
python translate.py glossary add "Snape" "Снейп" --lang uk

# Додати/виправити російську форму
python translate.py glossary add "Snape" "Снегг" --lang ru

# Додати новий термін (ОС-персонаж)
python translate.py glossary add "Selene Nightwood" "Селена Найтвуд"
```

## Рівні якості та ціни

Флаг `--quality` вибирає модель Claude для перекладу глав.
Авто-збір імен завжди виконується на Haiku (дешева структурна задача).

| `--quality` | Модель | Вхід $/1M | Вихід $/1M | Орієнт. вартість 100k слів |
|-------------|--------|-----------|------------|---------------------------|
| `fast` | `claude-haiku-4-5` | $1.00 | $5.00 | ~$0.30–0.50 |
| `balanced` *(за замовч.)* | `claude-sonnet-4-6` | $3.00 | $15.00 | ~$1.00–1.50 |
| `max` | `claude-opus-4-8` | $5.00 | $25.00 | ~$1.80–2.50 |

> Кешування system-prompt (~90% економії на глосарії) враховано у всіх рівнях.
> Реальна вартість відображається до запуску — якщо є `ANTHROPIC_API_KEY`,
> рахується точно через `count_tokens` API, інакше евристично.

**Рекомендації:**
- `fast` — чернетка, дуже великий фанфік (500k+ слів), або тест пайплайну.
- `balanced` — рекомендується для більшості фанфіків: якісний переклад за розумну ціну.
- `max` — фінальна якість, складна проза, важливий нюанс стилю.

## Двомовний глосарій

`glossary.json` — тримовний канон по англійському ключу:

```json
{
  "Hogwarts": { "ru": "Хогвартс",  "uk": "Гоґвортс" },
  "Snape":    { "ru": "Снегг",     "uk": "Снейп"    },
  "Muggle":   { "ru": "маггл",     "uk": "маґл"     }
}
```

- При `--from en --to uk` глосарій дає `Hogwarts → Гоґвортс`.
- При `--from ru --to uk` глосарій дає `Хогвартс → Гоґвортс` — тобто
  термін матчиться у тексті на кирилиці.

**Базовий UK-канон** (переклад В. Морозова / видавництво «А-БА-БА-ГА-ЛА-МА-ГА»):
Hogwarts→Гоґвортс, Dumbledore→Дамблдор, Snape→Снейп, Voldemort→Волдеморт,
Muggle→маґл, Quidditch→квідич, Gryffindor→Ґрифіндор, Slytherin→Слизерин,
Ravenclaw→Рейвенклов, Hufflepuff→Гафелпаф, Death Eater→смертежер тощо.

Частина форм спірна між виданнями — правте під себе командою
`glossary add "English" "Ваш варіант" --lang uk` або прямо у файлі.

## Авто-збір імен

Перед перекладом (якщо не вимкнено `--no-collect-names`) інструмент:

1. Сканує весь текст регулярним виразом заголовних токенів.
2. Відкидає слова, що зустрічаються **тільки** на початку речення
   (там заголовна не є ознакою власного імені).
3. Залишає кандидатів, які зустрічаються ≥ 3 рази в середині речення
   і ще не є у глосарії.
4. Надсилає один запит до Haiku: «переведи ці імена для HP-фанфіку, JSON».
5. Результат додається до глосарію на цей прогін (канонічні форми
   мають пріоритет над авто-зібраними).

```
Зафіксовано імен для консистентності: 12
```

Таким чином ОС-персонажі, вигадані автором заклинання та локації мають
єдиний переклад у всіх главах.

## Перевірка консистентності

Після генерації `.docx` готовий текст автоматично сканується на
різнобій написань. Перевіряються типові помилки для українського тексту:

| Конфузабельна пара | Приклад |
|--------------------|---------|
| `г` ↔ `ґ` | Гоґвортс / Ґоґвортс |
| `и` ↔ `і` | Гридор / Грідор |
| `е` ↔ `є` | Северус / Сєверус |
| `ї` ↔ `і` | — |
| апостроф / без | ім'я / імя |

Якщо знайдено — виводиться попередження (без зупинки):

```
⚠ Можливий різнобій написань (2):
  Гоґвортс — зустрічаються також: Ґоґвортс
  Снейп — зустрічаються також: Снейп (без апострофа)
Поправте вручну або зафіксуйте форму: glossary add "English" "Канон" --lang uk
```

## Форматування виводу .docx

- Шрифт Georgia 12pt, міжрядковий інтервал 1.5
- Поля 2.5 см з усіх боків
- Заголовки глав — Georgia 14pt Bold
- Зміст автоматично на першій сторінці (після титулу)
- Колонтитул: назва книги + номер сторінки
- Підпис: «Переклад виконано FanTranslate» (для `--to uk`)

## Архітектура

```
translate.py            CLI (typer + rich)
config.py               модель, мови, ціни, ліміти, .env
glossary.json           тримовний HP-глосарій

core/
  parser_epub.py        ebooklib + BeautifulSoup → глави
  parser_pdf.py         pdfplumber → сирий текст по сторінках
  cleaner_pdf.py        пайплайн очищення + детекція глав
  translator.py         AsyncAnthropic: caching, чанкінг, retry, semaphore, мови
  glossary_builder.py   авто-збір повторюваних власних імен
  consistency.py        пост-перевірка різнобою написань
  estimator.py          оцінка вартості (count_tokens / евристика)
  exporter_docx.py      python-docx → .docx
  storage.py            SQLite: projects / chapters / translations
  models.py             датакласи Chapter, TranslationResult
```

**Потік даних:**

```
Файл → parser_epub / parser_pdf → cleaner_pdf
     → glossary_builder (авто-збір імен, 1 запит Haiku)
     → Translator (asyncio, до 5 паралельних запросів)
         └─ кожна глава → split_into_chunks → _request (retry)
         └─ зберігається в SQLite одразу після перекладу
     → exporter_docx → .docx
     → consistency.find_inconsistencies → попередження
```

**Чанкінг:** Глави довші 3000 слів діляться на частини з перекриттям 200 слів;
перекриття передається моделі як контекст і не дублюється в результаті.

**Кешування промптів:** Глосарій + правила кешуються після першого запиту.
Для книги на 30 глав це ~90% економії на системному промпті (читання кешу ×0.1).

## Тести

```bash
python -m pytest tests/
python -m pytest tests/ -v        # детально
python -m pytest tests/ -q        # коротко
```

Тести не вимагають API-ключа: перекладач і авто-збір імен перевіряються з
мок-клієнтом.

Покриття:
- `test_glossary.py` — завантаження/збереження, `glossary_pairs` для EN→UK і RU→UK,
  детермінізм рендеру, кеш-контроль
- `test_translator.py` — system-prompt, retry, валідація, вартість
- `test_glossary_builder.py` — витяг кандидатів, фільтрація, `collect_names` з mock
- `test_consistency.py` — детекція г/ґ, апостроф, відсутність хибних спрацьовувань
- `test_chunking.py` — розбиття на чанки, перекриття
- `test_storage.py` — SQLite: проєкти, переклади, resume
- `test_cleaner_pdf.py` — очищення PDF

## Вартість

| Сценарій | `fast` (Haiku) | `balanced` (Sonnet) | `max` (Opus) |
|----------|---------------|---------------------|--------------|
| Фанфік 50k слів | ~$0.15–0.25 | ~$0.50–0.75 | ~$0.90–1.25 |
| Фанфік 100k слів | ~$0.30–0.50 | ~$1.00–1.50 | ~$1.80–2.50 |
| Фанфік 300k слів | ~$0.90–1.50 | ~$3.00–4.50 | ~$5.40–7.50 |

> Авто-збір імен — один додатковий запит на книгу (Haiku, копійки незалежно
> від розміру).

Точна оцінка до запуску:

```bash
# Оцінка без перекладу (запускає до API count_tokens, якщо є ключ)
python translate.py translate book.epub --quality max
# Показує "Оцінка: ~$X.XX" — тоді Ctrl+C щоб скасувати
```
